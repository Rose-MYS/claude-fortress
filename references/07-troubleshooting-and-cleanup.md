# 07｜事故时间线、高频排障、线路优化与可恢复清理

> 汇总统一时间戳的排障取证模板、实战踩坑案例、单变量线路优化法，以及可核对的 5 步本地数据隔离清理流程。

---

## 1. 统一时间戳「事故时间线」模板（排障第一步）

遇到登录失败、受限、断流或异常报错时，**先建时间线，禁止盲目换 IP/重装**：

| UTC / 本地时间 | 事件类别（账号通知 / 客户端报错 / 网络变更 / 服务状态） | 原始证据（状态码 / Request ID / 日志摘要） | 性质（事实 / 推断 / 未知） |
|---|---|---|---|
| `YYYY-MM-DD HH:MM` | 例：客户端返回 `403` | `error.type`、原始报文（脱敏） | 事实 |
| `YYYY-MM-DD HH:MM` | 例：上游入口变动或宿主机切 TUN | 网关/客户端日志 | 事实 |

### 常见状态码客观分诊（不把推断当结论）
| 状态码 / 现象 | 常见可能原因（须结合证据核实） | 正确动作 |
|---|---|---|
| 跳转 `/restricted` 或官方邮件通知 | 账号已被限制或暂停 | 立即停止重试，保留证据，走 Anthropic 官方申诉渠道 |
| `403 permission_error` | API 的该错误类型表示资源或权限不允许；Web 403 不是同一种证据 | API 核对权限与请求 ID；Web 区分官方页面、代理或上游响应，保留脱敏原文，不推断账号或 IP 被限制 |
| `429 rate_limit_error` | 触发 RPM/TPM 速率限制、并发过高或配额耗尽 | 查看响应头 `retry-after`，降低并发并等待窗口恢复 |
| `529 overloaded_error` / `5xx` | 上游服务端临时过载或故障 | 查询官方状态页，等待恢复，勿折腾本地网络 |

## 2. 高频实战排障案例

1. **宿主机开 TUN 导致 VM 超时 / 假 2 ms 延迟**：
   - **根因**：宿主机 TUN 劫持 `vmnat.exe` 流量，造成双层代理嵌套与 `198.18.0.0/16` Fake-IP 冲突。
   - **解法（先检查实际影响；改变隔离边界时 C 档）**：确认宿主机无其他依赖宿主 TUN 的 NAT 客机后，在规则模式前置 [../assets/host-clash-vmnat-bypass.yaml](../assets/host-clash-vmnat-bypass.yaml)（**不含 `MATCH`**），复测宿主机原规则与 VM 双路径。
2. **OpenWrt 网关启动文件缺失导致 VM 断网**：
   - **解法**：先带外停机确认目标盘、快照链、每级描述文件及其 backing 文件、父子关系、容量和已知好版本 SHA-256；尺寸一致不代表完整。仅恢复经核对的描述文件，不覆盖新工作或数据盘。启动前保留独立回退副本，恢复后重验启机与网关边界。
3. **出口 IP 正确但解析路径或连通性异常**：
   - **解法**：`scripts/claude-env-check.ps1` 只采 HTTP 功能观测，不能证明 DNS 路径。回看解析日志和 WAN 出站证据；未知不放行。

## 3. 单变量线路优化测量流程（可选，P2）

出现晚高峰卡顿或高延迟时，**每次只改一个变量**，不要盲目堆叠中转：
1. **分段定位**：分别测量 `客机 → 网关`、`宿主机 → 上游入口`、`经代理 → 中性目标` 三段延迟，确认瓶颈在哪一段。
2. **同口径对比**：在同一时段、同一中性目标、同一测量方法下，对比连接耗时、丢包率、重传与吞吐。
3. **改后重验**：任何传输协议或路由优化后，必须重跑 **S1 中性预验收 + Fail-Closed 负向演练**。

## 4. 5 步可恢复本地数据隔离清理（C 档）

> **原则**：默认**先备份移走（可恢复隔离），不直接永久删除**；源码、未提交 Git 工作、其他 Agent 配置、用户的 `settings.json` / `skills/` / `plugins/` 与取证日志始终受保护。

1. **确认前置条件**：完全退出所有 Claude 客户端（含 Windows MSIX/传统安装版）与 CLI 进程，确认当前登录用户与目标目录归属。
2. **生成只读清单（A 档）**：列出拟清理路径、文件大小与数量；**单独询问用户**是否将本地历史对话记录一并隔离归档。
3. **私有备份与哈希核对（B 档）**：将拟清理对象复制到宿主机私有备份目录，记录路径、大小与 SHA-256 清单。
4. **C 档确认后执行隔离**：仅移动私有清单中复核过的具体缓存文件，不移动整个安装、配置、浏览器 Profile 或会话父目录。逐项检查目标、所有者、链接/重解析点、排除项和备份哈希；日志先作取证归档，不把日志目录当垃圾。会话数据与目标站点数据分别明确确认；禁止通配删除及扫描、复制其他账号的内容。
5. **恢复核对**：确认被保护目录与源码完好无损，并向用户提供备份位置与手动还原路径。
