# 01｜路线选型、S0 离线盘点与 S1 中性证据契约

> 配合 `SKILL.md` 的五阶段门禁使用：本手册只覆盖 **S0（离线盘点）** 与 **S1（授权的中性预验收）**，**绝不在预验收阶段接触任何 Claude / Anthropic 端点**。

---

## 1. 四条路线对比与边界定位

| 维度 | A1：指纹浏览器 + CLI 隔离 | A2：本机整机防护 | B：VM + OpenWrt 隔离堡垒（主力） | C：远程 VPS 开发机 |
|---|---|---|---|---|
| **隔离本质** | **应用层分流（非 Fail-Closed）** | 系统级 TUN + OS 防火墙 | **客机外网关 + 客机内 GPO（待验收）** | 远端 Linux 隔离 |
| **成熟度** | 模板 | 参考设计 | 参考实现 · 未实机验收 | 参考设计 |
| **系统开销** | 极低 | 低 | 中高（建议宿主机 ≥16 GB 内存、≥80 GB 磁盘） | 本地零开销 |
| **Claude Web / Code** | ✅ / ✅ | ✅ / ✅ | ✅ / ✅ | ⚠️ / ✅ |
| **Claude Desktop** | ❌ 不建议宿主机裸装 | ⚠️ 风险较高 | ✅ 关在 VM 笼子内 | ❌ 不推荐 |
| **防扫描宿主机** | 无（同 OS 权限） | 无 | **高（仅暴露显式只读/受限共享区）** | **高** |

## 2. S0：A 档纯离线盘点（不发任何网络请求）

Agent 仅通过本机只读命令采集事实，只在对话输出脱敏摘要；落盘须另获 B 档批准（参考 [../assets/session-state.example.json](../assets/session-state.example.json)）：
1. **系统与硬件**：OS 版本、虚拟化支持、可用内存与磁盘空间。
2. **网络拓扑**：物理/虚拟网卡别名、是否启用 IPv6、现有默认网关、已运行的代理客户端进程路径。
3. **虚拟化环境**（路线 B）：VMware Workstation 版本、VMnet8 网段、是否存在其他 NAT 客机。
4. **工具链**：Python（3.10+）、Git、OpenSSH 客户端与服务端可用性。

## 3. S1：B 档中性预验收证据契约（零 Claude 端点接触）

> **重要**：向中性第三方发探测请求会暴露来源 IP，须先获用户 B 档同意。本阶段**不得**测试 `claude.ai` 或 `anthropic.com`；每项证据必须明确记录为 `pass` / `fail` / `unknown` / `not_run`，未采证一律记 `unknown` 或 `not_run`，**禁止补绿**。

### 3.1 正向功能验收（全部在目标隔离环境内采集）

| 证据项 | 中性采证方式 | 通过标准 |
|---|---|---|
| **IPv4 出口一致性** | 用至少两个独立中性端点（如 `api.ipify.org`、`ifconfig.me/ip`）分别测直走 TUN 与显式本地代理端口 | 全部返回同一预期 `<RESIDENTIAL_EGRESS_IP>` |
| **IPv6 阻断** | `curl -6 --max-time 4 https://api64.ipify.org` 及网卡 IPv6 绑定核查 | 超时/失败只是线索；结合 IPv6 绑定/路由和 WAN 负向证据，不明则 unknown |
| **DNS 归属与无泄漏** | 核对代理 DNS 日志、目标端实际解析行为与网关 WAN 抓包 | 无未经授权 DNS 直出；HTTP 回显 IP/地区不能证明 DNS 路径 |
| **浏览器 WebRTC 探测** | 仅在目标浏览器 Profile 内用本地或中性 WebRTC 探测页核查 | 不暴露宿主机内网/公网真实 IP |
| **跨时段稳定性** | 早、晚高峰、深夜至少 3 个时段记录同一配置代际下的出口 IP | 三次完全不变 |

### 3.2 负向边界验收（发布/启用前硬门槛）

仅有“能上网”不能证明 Fail-Closed 生效，路线 A2 / B / C2（代理默认拒绝）必须通过负向验证；C1 只按原生出口契约验证，不宣称代理断线阻断：
1. **冷启动测试**：系统/VM 刚开机、代理尚未拉起前，客机或网关 WAN 侧抓包/计数器不得出现未授权公网出站。
2. **入口失效演练**：在网关或防火墙侧对当前上游入口施加限时阻断（实际阻断属于 C 档，保留并新建管理 SSH 验证），确认目标环境彻底无法回退直连公网；阻断到期后自动恢复双路径。

> **S2 过渡**：仅当 S1 正向与负向证据关键适用项全部为 `pass`（`unknown`、`not_run` 不放行） 时，才向用户出具 **C 档确认单**，由用户本人决定是否进入 S2（首次接触官方服务）。
